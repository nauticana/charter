# Capability SDK

`Catalog` serves capability contracts (`BaseCatalog`); `VersionPolicy` decides contract compatibility. `BaseInvoker` runs the governed pipeline around an abstract `binding.Executor`: version, actor lifecycle, authority, approval, separation of duties (`SodChecker`), information governance (`Invocation.InformationUses` against `information.Evaluator`, decisions evidenced), binding feature support, idempotency (`Ledger`, whose fenced claim reaches the caller as `Result.LedgerFence` for reconciling an unknown outcome), execution, declared-outcome and business-error verification, effect verification (a `binding.Observer` evaluates the contract's postconditions after an accepted mutation; executed needs every required one satisfied on observed-fact evidence, a violation is failed or its mapped business error, and anything else is unknown), and an `ActionRecord` appended to the evidence sink for every decision. `Invocation.AuthorityChain` carries a downstream-verified acting path into authority and approval checks; any hop's approval bound requires approval, and SoD includes the performed-action history of the actor and every delegator. An `Escalator` (`BaseEscalator` over `BaseAccountableRecipient`) turns unknown and failed outcomes into an `ExceptionRecord` and an `Escalation` to the accountable authority of the agent's definition. `Reconciler` (`BaseInvoker.Reconcile`) settles an unknown attempt from observation alone: it proves the fence, never calls the transport, and appends a record naming the attempt it reconciles; an effect observed absent releases the key only when the contract sets `idempotency.retryWhenEffectAbsent`. Tool and system adapters implement the transport and the observer; they never replace the contract.
