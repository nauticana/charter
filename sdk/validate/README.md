# Validation Package

`Validator` interface implemented by the structural validator (embedded schemas), the `SpecVersion` check, and by every semantic `Rule` (concrete rule types embedding `AbstractRule`); `Runner` executes manifest fixtures and generates a `ConformanceClaim` for an active profile (`Claim`), partial when any profile rule could not be tested. `Additions` validates documents before a store commits them: structure, the catalog's specification version, references resolved against a `corpus.Source`, and the fixed derivation of a published version it replaces, a new version of a versioned definition recording its own, fetching only the written and referenced documents so the cost follows the write, and reporting only findings about the written documents. Results carry stable rule ids, normative requirement ids, verification classes, and document paths. `SchemaMeta` reads the kinds and the idRef- and objectRef-typed properties from the embedded schemas; `WalkRefs` visits every reference below a document value, handing each reference value to a caller that may rewrite it.

`ManifestReader` validates `manifest.yaml`, rule definitions, and fixture descriptors against the embedded conformance format schemas before decoding them. Runtime-behavioral rules (`BehavioralRule`, `NewBehavioralRuleSet`) execute a fixture's `Scenario` against a `Subject`, the runtime under test that composes a `Runtime` (admission, invoker, reconciler, evidence) over the scenario documents while the harness scripts the `External` system: the transport that mutates it and the observer that reads facts and effects back, which reports unscripted postconditions as unknown; `ReferenceSubject` is the SDK itself and the runner's default. System-adapter rules instead judge an `AdapterSubject`, which realizes the scenario's capability binding over a scripted `VendorEndpoint`; `ReferenceAdapter` is `AbstractBinding` over a neutral status/reference vendor protocol.
