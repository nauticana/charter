# Validation Package

`Validator` interface implemented by the structural validator (embedded schemas), the `SpecVersion` check, and by every semantic `Rule` (concrete rule types embedding `AbstractRule`); `Runner` executes manifest fixtures and generates a `ConformanceClaim` for an active profile (`Claim`), partial when any profile rule could not be tested. Results carry stable rule ids, normative requirement ids, verification classes, and document paths.

`ManifestReader` validates `manifest.yaml`, rule definitions, and fixture descriptors against the embedded conformance format schemas before decoding them. Runtime-behavioral rules (`BehavioralRule`, `NewBehavioralRuleSet`) execute a fixture's `Scenario` against a `Subject`, the runtime under test that composes a `Runtime` (admission, invoker, evidence) over the scenario documents while the harness scripts the transport; `ReferenceSubject` is the SDK itself and the runner's default. System-adapter rules instead judge an `AdapterSubject`, which realizes the scenario's capability binding over a scripted `VendorEndpoint`; `ReferenceAdapter` is `AbstractBinding` over a neutral status/reference vendor protocol.
