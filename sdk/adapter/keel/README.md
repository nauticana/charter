# Keel Adapter

Optional bridge from Charter's neutral contracts to the primitives keel exposes; Charter's core packages never import keel, and keel never imports Charter. Only keel's `port`, `common`, `model`, and `guard` packages are used, so no cloud SDK enters the build. The tables the stores query are a keel schema module in [`schema/`](schema/): pass `schema/document` (and `schema/identity` for account links) to keel's `schemagen -input` after keel's `core`, `geo`, and `tenant_management`.

- keel's `common.CallerSessionFromContext` supplies the authenticated caller; `RuntimeContext` turns its request id into the execution context of an action.
- `IdentityMap` connects keel subjects to Charter identities and maps an actor to the keel grant principal evaluated for it. `BaseClaimIdentityMap` reads identity claims, maps humans to `model.UserPrincipal`, and maps agents to `Principal{Kind: AgentPrincipalKind, ID: actor.ID, Scope: []any{session.PartnerID}}`; `Caller` resolves the acting identity active at the action time. The agent grant source contract is subject `agent_id` (the exact stable Charter `AgentIdentity` id) with sole filter `tenant_id`; downstreams reference `AgentPrincipalKind` rather than repeating `"agent"`.
- `Gate` protects keel's boundaries: `Middleware` over a `Routes` table for HTTP (generated CRUD included, by path), `Handler` for table actions and custom endpoints (alone or inside `handler.WrapTableAction`), and `Check` for workers, which bind the principal they claimed with the job through `common.WithCallerSession`. A gate establishes the active identity and an effective grant for the capability and hands a `Clearance` down the context; limits, approvals, separation of duties, and information governance remain the invoker's at the action boundary.
- `PermissionGate` is an `authority.Evaluator` that layers keel's principal-aware `CheckActionPermission` behind a Charter evaluator: keel may deny, never widen, and unmapped capabilities fail closed. A custom `IdentityMap` must return scope values in the exact order required by its registered grant source.
- `GuardedInvoker` runs a `guard.TrustGuard` chain before the governed pipeline; duplicates report an unknown outcome to reconcile, policy refusals deny.
- `Ledger` backs `capability.Ledger` with `port.IdempotencyLedger`, so keel's memory or PostgreSQL ledger keeps replay results and fenced claims, including the reconciliation fence `ReclaimUnknown` grants.
- `TableLogStore` is an `evidence.Store` over a `ChangeLog`, a `port.TableLogger` that is also a `port.ChangeQuerier` (keel's change filter has no payload index, so `evidence.BaseProvider.ActionsIn` over it scans); `PublishingSink` publishes every appended document, redacted, through `port.MessagePublisher` (back it with the outbox downstream).
- `DocumentStore` keeps a tenant's Charter documents in `charter_document` and its append-only `charter_document_revision`; `Source(partnerID)` is the `corpus.Source` providers read. `Save` validates structure and references (`validate.Additions`, which fetches only the documents the write references), commits a batch atomically, treats identical content as a replay, and refuses evidence kinds, kind or enterprise changes, and different content under a stored definition version (`corpus.DefinitionVersion`).
- `HumanAccounts` keeps `charter_human_account`, a child of keel's `partner_user` and of the stored `HumanIdentity`: a link lies within its membership and never overlaps another link of the same human or user, which PostgreSQL also enforces through exclusion constraints (`btree_gist`). `TableIdentityMap` resolves a human session's keel user (the `keel_user_id` claim, else the `user:<id>` subject keel's authorization server mints) through the link effective now and requires no Charter claims; agent sessions keep `BaseClaimIdentityMap`.
- Every module table carries `partner_id` in a foreign key that reaches `business_partner`, directly or through a composite key, so keel's generic CRUD pins all three to the caller's partner.
- `BigintIDs` mints evidence ids from `port.BigintGenerator`; `MetricsInvoker` counts invocations through `port.MetricsRecorder`.
