# Architecture States, Gaps, and Roadmaps

Status: Version 1.0.0

Charter represents current and intended enterprise arrangements without requiring a particular enterprise-architecture method.

## Requirements

- **CHR-ARCH-001:** An architecture element MUST be attributable to an architecture state or explicitly identified as state-independent.
- **CHR-ARCH-002:** A baseline state MUST describe observed or approved current conditions and its effective context.
- **CHR-ARCH-003:** A target state MUST describe intended conditions and the decision authority that approved or proposed them.
- **CHR-ARCH-004:** A gap MUST reference the compared baseline and target elements and classify the missing, changed, or retired condition.
- **CHR-ARCH-005:** A roadmap item MUST reference the gaps or outcomes it addresses and declare dependencies, ownership, and status.
- **CHR-ARCH-006:** Architecture states MUST be versioned or time-bounded so that later changes do not rewrite historical analysis.
- **CHR-ARCH-007:** An implementation that produces an architecture recommendation MUST NOT imply that every architecture gap requires an AI agent or automation solution.

Business, information, application, and technology views may be aligned with TOGAF or another method, but those external methods are not incorporated into Charter by reference unless a specification release explicitly says so.
