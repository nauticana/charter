# Security Policy

Nauticana Charter currently contains a draft specification and supporting documentation, not production software. Security reports may nevertheless concern unsafe normative requirements, schemas, examples, dependency choices, or future reference implementation code.

## Reporting a vulnerability

Use the repository host's private vulnerability-reporting feature when it is available. If it is unavailable, contact a maintainer privately. Do not include exploit details, credentials, confidential enterprise data, or customer information in a public issue.

Include the affected artifact and version, expected and observed behavior, impact, reproduction conditions, and any proposed mitigation. Maintainers will acknowledge the report, assess its scope, coordinate a correction, and credit the reporter when requested and appropriate.

## Supported versions

No stable specification or software version has been released. Support commitments will be documented with the first release.

## Security scope

Charter conformance does not by itself establish that an implementation is secure. Implementers remain responsible for authentication, credential storage, isolation, authorization enforcement, data protection, dependency security, deployment hardening, monitoring, and incident response.
